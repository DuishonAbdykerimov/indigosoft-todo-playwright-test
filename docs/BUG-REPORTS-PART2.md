## Сценарии и результаты

### 1. Добавление задачи с пустым текстом

**Шаги:** оставить поле пустым или ввести только пробелы → нажать **Add**.

**Ожидание:** задача не создаётся, пользователь видит подсказку об ошибке.

**Факт:** задача не создаётся (`addTask` проверяет `title.trim()`), счётчик списка не меняется.

**Вывод:** функционального бага нет. Зафиксирован **BUG-006** (UX): нет сообщения, кнопка «молча» ничего не делает.

---

### 2. Очень длинный текст задачи

**Шаги:** добавить задачу с текстом 800–5000 символов.

**Ожидание:** текст отображается читаемо (перенос, обрезка, tooltip).

**Факт:** задача добавляется и видна, но строка растягивает блок (`scrollWidth` ≫ ширина контейнера), появляется горизонтальный overflow.

**Вывод:** **BUG-005**.

---

### 3. Специальные символы (`<`, `>`, `&`, `"`, `'`)

**Шаги:** добавить задачу с текстом вида `<tag> & " quote`.

**Ожидание:** символы показаны как текст, без XSS и поломки разметки.

**Факт:** в списке отображается литеральная строка `<tag> & " quote`, тег `<script>` не исполняется (Angular `{{ }}` экранирует HTML).

**Вывод:** дефект не воспроизведён.

---

### 4. Много задач подряд (20+)

**Шаги:** подряд добавить 25 уникальных задач с паузой ~80 ms.

**Ожидание:** все 25 отображаются в списке.

**Факт:** в UI найдено **23 из 25** (2 задачи не появились).

**Вывод:** **BUG-003** — гонка запросов / нет блокировки кнопки Add во время запроса.

---

### 5. Быстрое нажатие кнопки Add

**Шаги A:** 10–15 быстрых кликов **Add** с одним текстом в поле (поле ещё заполнено).

**Факт A:** после первого клика поле очищается в шаблоне → в списке обычно **1** задача (корректно).

**Шаги B:** два быстрых **Add** подряд с одним текстом до очистки input.

**Факт B:** в списке **2** одинаковые задачи.

**Вывод:** **BUG-002** при двойном сабмите; массовые дубликаты при «молотилке» по одной кнопке ограничены очисткой поля.

---

### 6. Переключение фильтров после изменений

**Шаги:** добавить активную задачу → **Active** / **Completed** → отметить выполненной → снова **Completed** и **Active**.

**Ожидание:** задача видна только в подходящих фильтрах.

**Факт:** поведение соответствует ожиданию (активная только в All/Active, выполненная — в Completed).

**Вывод:** дефект не воспроизведён.

---

### 7. Редактирование задачи

**Шаги:** добавить 2 новые задачи → **Edit** на одной.

**Ожидание:** режим редактирования только у выбранной строки.

**Факт:** открываются **2** поля `input.edit-input` одновременно.

**Причина:** JSONPlaceholder на каждый `POST` возвращает **`id: 201`**. В шаблоне условие `currentTask?.id !== task.id` — при совпадении id редактируются все такие задачи.

**Дополнительно:** сохранение и удаление могут затронуть «чужую» задачу с тем же id.

**Вывод:** **BUG-001** (корневая причина проблем редактирования).

Для задач, загруженных с API с уникальными id (1–10), редактирование одной строки работает.

---

### 8. Удаление всех задач

**Шаги:** удалить все задачи кнопкой **Delete** по одной.

**Ожидание:** пустой список и понятное сообщение «Нет задач».

**Факт:** список пустой, блок `.task-list` без элементов и **без** текста-подсказки.

**Шаги:** перезагрузить страницу после удаления всех.

**Факт:** снова подгружаются ~10 задач с API (mock не хранит удаления).

**Вывод:** **BUG-004** (UX пустого списка); поведение после reload — **ограничение mock API**, не локального хранилища.

## Детальные баг-репорты

### BUG-001 — Одинаковый id у всех новых задач ломает редактирование

| Поле | Значение |
|------|----------|
| **Severity** | Critical |
| **Компонент** | `TodoService.addTask` + `task-list.component.html` |
| **Окружение** | Chrome, `localhost:4200` |

**Шаги воспроизведения:**
1. Открыть приложение.
2. Добавить задачу «Задача A».
3. Добавить задачу «Задача B».
4. Нажать **Edit** у «Задача A».

**Ожидаемый результат:** режим редактирования только у «Задача A».

**Фактический результат:** поля редактирования у обеих новых задач (2× `input.edit-input`).

**Техническая причина:** `POST /todos` всегда отвечает `{ id: 201, ... }`. Условие `*ngIf="currentTask?.id !== task.id"` не различает строки.

**Рекомендация:** генерировать локальный уникальный id (например `Date.now()` / uuid) до ответа сервера или не полагаться на mock-id.

### BUG-002 — Дубликаты при быстром двойном Add

**Ожидание:** одна задача.

**Факт:** две задачи с одинаковым названием.

**Рекомендация:** debounce / disable кнопки на время запроса.

| Поле | Значение |

**Ожидание:** 25 задач в списке.

**Факт:** 23 задачи (2 потеряны).

**Рекомендация:** блокировать UI во время `subscribe`, очередь запросов или batch.

|------|----------|

**Рекомендация:** `word-break`, `max-width`, `text-overflow: ellipsis`, опционально `maxlength` на input.

## Ограничения среды (не баги приложения, но важно для тестировщика)

1. **Reload:** пользовательские задачи пропадают — данные не персистятся (mock API).
2. **Удаление всех + reload:** задачи возвращаются с сервера (`getTasks?_limit=10`).
3. **Пустой ввод:** отклоняется на уровне кода — корректная валидация.
